## Answers to the checklist

1. **Can a cold reader start?** Yes, with guesses at: install location (C-02); whether to make the project venv (C-12); `uv` (C-06); the meaning of "round" in the G0 cell (C-04); how to write `{{SHEET_AND_REFDES_CONVENTION}}` and `{{FAB_CONSTRAINTS}}` (`templates/CLAUDE.md:21,26` give only "e.g."); what SPEC.md and VERIFY.md must look like (C-08); when the CC-001 row is "written" (C-13); why step 6 exits 1 (C-14). The replay itself is otherwise smooth: 32 placeholder names, every selftest green, adopt + clone gate green, hand-off header reads "no board in HEAD" as promised.
2. **Completeness per phase.** G0 (spec): inputs, roles, pack, verdict, decider — complete except the SPEC/VERIFY shapes. G0→G1: `schematic-phase.md` is the best reference in the repo (yaml shape, ERC command, map checks, pack table, order of operations). **G1→G2 is the thinnest** (C-07). Submission: fab-package contract exists only as §8 of `fab-dfm.md` plus the placed-order freeze; the package generator's inputs are implied. Release/production cut: complete on paper, generator project-side by design. Case/FEA/software: mechanism-rich, decider-poor (C-17). CNC enclosures are promised in the description and covered by three lines (`fab-dfm.md:72-73`).
3. **Contradictions:** C-01, C-03, C-04, C-05, C-13, C-18, C-19, C-21, C-22, C-23; minor: `quiet_regex` `'Fontconfig|wxApp|Debug:'` (`project-yaml.md:89`) vs `'Fontconfig|wxApp'` (`templates/project.yaml:57`).
4. **Dead references / leaks:** no cited skill file is missing (every `references/`, `templates/`, `scripts/`, `workflows/` path resolves; `docs/*` paths are the project's own). Ambiguous: §7.7 (C-20). Leaks: C-15, C-25, C-27; the JLC/LCSC endpoints, KiCad and Bambu facts are labelled worked examples and acceptable.
5. **Runnability:** everything runs; no script fails; `--help` is read-only everywhere (`git status` clean after the sweep). Undeclared: numpy/trimesh/shapely, uv (C-06). Hard-coded: `WALL_DEG = 30` (`thin_wall_census.py:27`), the histogram bins, `{KICAD_CLI}`-family placeholders (C-16). Templates: CI placeholders are documented with a sed recipe; `production_cut.yaml` placeholders `{{PCB_DRAWING_CHECK}}` etc. are clear; `DFM_ROUND.md` and `VENDOR_REVIEW_RECORD.md` are clear.
6. **Rule quality:** C-09, C-10. Good pattern to copy everywhere: `fab-dfm.md:80-83` ("values live then; fetch the current page before using them").
7. **Agent operations:** the strongest part of the skill — explicit-path commits, hunk isolation recipe, checkpoint commits, turn limit, read-only checkers, owner-list discipline, resume-by-measured-state are all clear enough not to repeat the listed pitfalls. Missing for a fresh agent: one consolidated "an agent never …" list (today spread over `agent-ops.md` §1/§2/§7, `SKILL.md` §1.1/§11, `vendor-review.md` §1); a PAUSE POINT skeleton in the STATUS template (C-30); a checkpoint-commit message convention beyond "say not yet gated"; an ID-reservation helper (the `grep -c` by hand is the collision the skill itself reports at `pitfalls.md:97`); the deferred `gate_status.py` (whether a cell is owner text is judged by prose since 0.2.0); guidance on worker count / fork vs fresh agent beyond "a fork stops at ~200 turns".
8. **Size and navigation:** 1561 reference lines + 283 SKILL are navigable through the Where-to-look table, but the printed-enclosure rules exist three times (`SKILL.md:180-211`, `dfm-printed-enclosure.md:9-131`, `pitfalls.md:9-52`) and the quote-page mechanics twice (`dfm-printed-enclosure.md:82-131`, `vendor-review.md:48-72`). Cut SKILL §8.1 to the acceptance bar + six one-line rules + pointer; make the pitfalls dfm section a one-line pointer; fold `vendor-review.md` §4 into `dfm-printed-enclosure.md` §7. Add a Where-to-look row per phase (G0, G1, G2, order, release, cut) rather than per topic, and a layout reference to fill the G1→G2 hole. `pitfalls.md` would read better grouped by phase with the source pointers stripped (C-27).

## Verdict

I could run a new project with this skill: the day-1 path replays green, every script is read-only on `--help`, self-tested and driven by `project.yaml`,
and the agent-operations discipline is the most complete I have seen written down. I would not get through the enclosure phase without hitting C-01
(the pasted census gate line does not parse) and I would spend the first hour guessing at C-02/C-12/C-06 (where the skill lives, which venv, which
extra packages). Fix first, in this order: C-01 (`--gate` → `--gate-dir` in the three prose copies), C-02 + C-12 + C-06 (one install block with the
project venv, `uv`, and the mesh-library line), C-03 (delete the retracted material rule), C-04 (define "round" once), then write the missing
G1→G2 reference (C-07) and qualify the FDM numbers with printer/material (C-09). The rest is polish that the next production cut can fold in.
